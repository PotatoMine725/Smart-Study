### 2.1 The six synced entities

| Class | Table | PK property | PK type |
|---|---|---|---|
| `HocKy` | `HocKys` | `MaHocKy` | `Guid` |
| `MonHoc` | `MonHocs` | `MaMonHoc` | `Guid` |

| `TaskNote` | `TaskNotes` | `Id` | `Guid` |
| `TaskReferenceLink` | `TaskReferenceLinks` | `Id` | `Guid` |

All six implement `ISyncMetadata` (`SmartStudyPlanner/Models/ISyncMetadata.cs`):
`long Rev`, `DateTime ModifiedAtUtc`, `string ModifiedByDeviceId`, `bool IsDeleted`,
`DateTime? DeletedAtUtc`. All six are exposed as `DbSet<T>` on `AppDbContext`
(`SmartStudyPlanner/Data/AppDbContext.cs`).

### 2.2 `Rev` is a per-row edit counter, not a global sequence — this determines the whole design

`SyncStamper.Apply` (`SmartStudyPlanner/Data/SyncStamper.cs:20-42`) does `meta.Rev++` on
the entity being saved. This increments **that row's own** counter. Two different rows
edited a different number of times will have unrelated `Rev` values — there is no global
total order across rows on one device, let alone across devices
(`docs/architecture/lessons-learned.md` L6: *"never compared across devices"*, and its
role is *"change enumeration since the last sync watermark + same-device ordering"*).

Consequence: **a "Rev watermark" cannot be a single scalar per peer.** It can only be a
**per-(peer, row) baseline Rev** — the value that row's `Rev` was the last time this
device successfully synced that specific row to that specific peer. That baseline lives
in the T1.4 snapshot row itself. The enumeration predicate for peer `P`, row `R` is:

```
include R  ⟺  no snapshot exists for (P, R.EntityType, R.Id)
             OR  R.Rev > snapshot.Rev
```

Do not build anything resembling a single "last sync timestamp per peer" fast-path filter
— it isn't required by the scope, and it reintroduces the exact cross-device-comparison
trap L6 documents.

### 2.3 No global query filter exists on the six DbSets

`AppDbContext.OnModelCreating` (read in full this session) contains no
`HasQueryFilter`. Tombstoned rows (`IsDeleted = true`) are excluded only by each
`Sqlite*Repository`'s own explicit `.Where(x => !x.IsDeleted)` — confirmed in
`SqliteStudyLogRepository`, `SqliteUserStatsRepository`, etc. Querying `db.HocKys`,
`db.StudyTasks`, etc. **directly** (not through a `Sqlite*Repository`) returns tombstoned
rows. This is exactly the property T2.2 depends on, and exactly the property a future
accidental `HasQueryFilter` addition would silently break — see the required regression
test in §6.2.

### 2.4 Existing schema-patch idiom to mirror exactly

Two idioms already exist for exactly this "add sync-adjacent infrastructure without
touching the six entities' tables" problem:

- `TelemetrySchema.EnsureOptimizerRunLogTable(db)` (`SmartStudyPlanner/Data/TelemetrySchema.cs:97-114`)
  — brand-new standalone table, `CREATE TABLE IF NOT EXISTS`, idempotent, no
  `DbBackup.CreateBackup` call (empty table, no user data at risk). Called once from
  `AppStartup.EnsureDatabaseReady` (`SmartStudyPlanner/Data/AppStartup.cs:41`).
- `OptimizerRunLogSchemaTests.cs` — the dual-path test shape: build a DB via
  `EnsureCreated()`, `DROP TABLE`, call the `Ensure*` method, assert the table exists
  again and round-trips; plus an idempotency test (call twice, no throw).
- `AppStartupFileBasedTests.EnsureDatabaseReady_OnPreT37Db_TaoLaiBangOptimizerRunLogs`
  — a *second*, independent regression guard: it proves `AppStartup` actually calls the
  schema seam, not just that the seam works in isolation. Its own comment explains why
  both tests are needed: removing the call site would leave the seam test green and a
  real user's DB silently missing the table.

**T1.4's new table follows this idiom exactly** — see §3.3. Do not invent a different
migration mechanism.

### 2.5 Repository layer is the wrong layer for T1.4/T2.2

`IHocKyRepository`, `ITaskEditorRepository`, etc. are aggregate-shaped domain ports
(`LayDanhSachHocKyAsync`, `GetBundleAsync`, ...), not generic CRUD, and their read paths
deliberately exclude tombstones. Sync infrastructure sits *below* that layer, alongside
`SyncStamper`/`SyncSchema`, and must bypass it entirely (§2.3). Do not add methods to any
`Sqlite*Repository` class for this slice.

### 3.4 `SmartStudyPlanner/Sync/SyncBaseSnapshotStore.cs`

Static class taking `AppDbContext db` as first parameter — mirrors `SyncStamper`/
`SyncSchema`/`TelemetrySchema`, **not** the `Sqlite*Repository(factory)` instance
convention (this is Data-layer sync infrastructure, not a domain port).

```csharp
namespace SmartStudyPlanner.Sync
{
    public static class SyncBaseSnapshotStore
    {
        public static Task<SyncBaseSnapshotRow?> GetAsync(
            AppDbContext db, string peerId, string entityType, Guid entityId,
            CancellationToken ct = default);

        // Keyed by EntityId, scoped to one peer + one entity type — this IS the
        // watermark lookup table T2.2 reads.
        public static Task<Dictionary<Guid, SyncBaseSnapshotRow>> GetAllForPeerAsync(
            AppDbContext db, string peerId, string entityType,
            CancellationToken ct = default);

        // Upsert. Find existing row by composite key; if present, overwrite Rev/
        // SnapshotJson/SyncedAtUtc in place; if absent, add new. Calls
        // db.SaveChangesAsync() itself (self-contained per call, matching how
        // Sqlite*Repository methods behave from a caller's perspective).
        public static Task SetAsync(
            AppDbContext db, string peerId, string entityType, Guid entityId,
            long rev, string? snapshotJson, DateTime syncedAtUtc,
            CancellationToken ct = default);

        public static Task DeleteAsync(
            AppDbContext db, string peerId, string entityType, Guid entityId,
            CancellationToken ct = default);
    }
}
```

Implementation notes:
- Use `db.SyncBaseSnapshots.FindAsync(new object[] { peerId, entityType, entityId }, ct)`
  for the upsert lookup (order must match the `HasKey` declaration in §5.1).
- `SyncBaseSnapshotRow` is never passed through `SyncStamper` in a way that matters
  (it doesn't implement `ISyncMetadata`, so `SyncStamper.Apply`'s
  `if (entry.Entity is not ISyncMetadata meta) continue;` skips it — confirm this with
  the reflection test in §6.1, don't just assume it).

### 4.2 `SmartStudyPlanner/Sync/SyncChangeEnumerator.cs`

```csharp
namespace SmartStudyPlanner.Sync
{
    public static class SyncChangeEnumerator
    {
        // Generic core predicate. allRows must come from the raw DbSet (db.HocKys,
        // db.StudyTasks, ...), never from a Sqlite*Repository — see §2.3/§2.5.
        public static async Task<List<ChangedEntity<T>>> EnumerateChangesAsync<T>(
            AppDbContext db, string entityType, IEnumerable<T> allRows,
            Func<T, Guid> idSelector, string peerId, CancellationToken ct = default)
            where T : class, ISyncMetadata
        {
            var baseline = await SyncBaseSnapshotStore.GetAllForPeerAsync(db, peerId, entityType, ct);
            var result = new List<ChangedEntity<T>>();
            foreach (var row in allRows)
            {
                var id = idSelector(row);
                if (!baseline.TryGetValue(id, out var snapshot) || row.Rev > snapshot.Rev)
                    result.Add(new ChangedEntity<T>(id, row, row.Rev, row.IsDeleted));
            }
            return result;
        }

        // Wires the generic predicate across all six synced entities for one peer.
        public static async Task<PeerChangeSet> GetChangesForPeerAsync(
            AppDbContext db, string peerId, CancellationToken ct = default)
        {
            return new PeerChangeSet(
                await EnumerateChangesAsync(db, SyncEntityTypes.HocKy,
                    await db.HocKys.ToListAsync(ct), h => h.MaHocKy, peerId, ct),
                await EnumerateChangesAsync(db, SyncEntityTypes.MonHoc,
                    await db.MonHocs.ToListAsync(ct), m => m.MaMonHoc, peerId, ct),
                await EnumerateChangesAsync(db, SyncEntityTypes.StudyTask,
                    await db.StudyTasks.ToListAsync(ct), t => t.MaTask, peerId, ct),
                await EnumerateChangesAsync(db, SyncEntityTypes.StudyLog,
                    await db.StudyLogs.ToListAsync(ct), l => l.Id, peerId, ct),
                await EnumerateChangesAsync(db, SyncEntityTypes.TaskNote,
                    await db.TaskNotes.ToListAsync(ct), n => n.Id, peerId, ct),
                await EnumerateChangesAsync(db, SyncEntityTypes.TaskReferenceLink,
                    await db.TaskReferenceLinks.ToListAsync(ct), l => l.Id, peerId, ct));
        }
    }
}
```
