## Scope

First milestone of Epic 1 (sync-ready data model). Builds the single stamping
seam (`ISyncMetadata` + `SyncStamper`) inside `AppDbContext`, and closes A6
(the fire-and-forget `StudyLog`/`StudyTimeOutcomeLog` writes in
`FocusViewModel`). Delete→tombstone + G1 cascade, entity metadata fields
(T1.1), and the schema-upgrade seam (T1.8) are explicitly **out of scope**
here — they belong to M1.2, whose header ("`[G1 closes here]`") is what
settled the ambiguity between the plan's upfront spine pseudocode (which
shows tombstone/cascade logic inline) and its milestone-by-milestone split.

## What shipped

1. **`Models/ISyncMetadata.cs`** — `Rev`, `ModifiedAtUtc`, `ModifiedByDeviceId`,
   `IsDeleted`, `DeletedAtUtc`. No production entity implements it yet.
2. **`Data/SyncStamper.cs`** — `Apply(ChangeTracker, Func<DateTime>, deviceId)`.
   Walks tracked entries; for any `ISyncMetadata` entity in `Added`/`Modified`
   state, increments `Rev` and stamps `ModifiedAtUtc`/`ModifiedByDeviceId`.
   Tested against a test-only entity + test `DbContext` subclass
   (`SyncMetadataStampingTests`), not real entities — keeps the M1.1/M1.2
   boundary clean instead of pulling M1.2's entity work forward.
3. **`AppDbContext`** — added a settable `Func<DateTime> Clock` (default
   `DateTime.UtcNow`, test-overridable; deliberately a plain delegate, not
   `IClock` via DI, since the context is parameterless-constructed and DI
   would wire `Data → Services.Strategies`). Overrode `SaveChanges(bool)` /
   `SaveChangesAsync(bool, CancellationToken)` — the two overloads every
   `DbSet` `Add`/`Update`/`Remove` call across all 9 repositories and
   `App.xaml.cs` routes through — to call `SyncStamper.Apply` before
   `base.SaveChanges...`. Currently a behavioral no-op for all production
   writes (zero entities implement `ISyncMetadata`).
4. **A6 (`FocusViewModel`)** — `LuuThoiGianThucTe` is now `async Task` and
   awaits both repository writes (previously `_ = repo.AddAsync(...)`).
   `HoanThanh()`/`ThoatKhanCap()` are `[RelayCommand(FlowExceptionsToTaskScheduler
   = true)] private async Task`, so a write failure is observable via the
   generated command's `ExecutionTask` instead of vanishing. Default
   `AsyncRelayCommand` behavior (await+rethrow) would crash the app on any
   save failure — worse than today's silent swallow for a mid-focus-session
   autosave — so `FlowExceptionsToTaskScheduler` was chosen deliberately.
   `StudyLog.DeviceId` is now stamped via `DeviceHelper.GetId()` at the write
   site (independent of the `ISyncMetadata` seam, since `StudyLog` doesn't
   implement it until M1.2's T1.1).
5. **Baseline timing harness** — `RepositoriesTests.TaskSave_P95Latency_Baseline`
   (50× `AddAsync`, Stopwatch, p95/mean reported via `ITestOutputHelper`, no
   hardcoded ms assertion — cross-machine/CI timing is noisy, so the number is
   measured and reported rather than baked into a flaky in-test threshold).

## Incidental fixes made along the way

- **Removed an orphaned duplicate test file.** `SmartStudyPlanner.Tests/Infrastructure/RepositoriesTests.cs`
  was a byte-identical leftover from an earlier "mirror production namespace
  layout" refactor (`b697eca`) that should have deleted the old-namespace
  copy but didn't — both ran as separate xUnit classes. Directly in this
  milestone's blast radius (the new baseline test landed in the surviving
  copy), so removed rather than left to diverge.
- **Fixed a `.gitignore` bug.** The unanchored `data/` rule (intended for a
  runtime SQLite data folder) case-insensitively matched the
  `SmartStudyPlanner/Data/` and `SmartStudyPlanner.Tests/Data/` **source**
  folders too, since this repo has `core.ignorecase=true` on Windows. It was
  silently swallowing new files added to those folders — including
  `SyncStamper.cs` from this very milestone, caught only because `git status`
  didn't show it as untracked after creation. No runtime `data/` folder
  actually exists at repo root (the SQLite file lives next to the built exe).
  Anchored to `/data/`.
