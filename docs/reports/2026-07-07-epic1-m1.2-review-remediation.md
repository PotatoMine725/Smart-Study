## Finding / fix

### M1.2-R1 — `SqliteStudyTaskRepository.DeleteAsync` skipped the G1 cascade (fixed)

**Problem.** `DeleteAsync` loaded only the `StudyTask` and called `db.StudyTasks.Remove(existing)`.
Pre-M1.2 this was a hard delete and the DB's `ON DELETE CASCADE` removed the task's `TaskNote`/
`TaskReferenceLink` for free. Post-M1.2, `SyncStamper` converts `Remove()` to a tombstoning
`UPDATE` instead of a real `DELETE`, so the DB-level cascade no longer fires — the task would be
tombstoned but its Note/Links left live, pointing at a dead parent. Exactly the G1 invariant this
milestone exists to establish, violated by a public repository method.

Reviewer noted this was **latent, not active**: `gitnexus_impact` confirmed `DeleteAsync` has
zero production callers (the UI deletes tasks through `LuuHocKyAsync`'s delete-by-absence path,
which already cascades correctly) and only one caller overall — its own childless round-trip test,
which never exercised the orphan because it never gave the task a Note or Link. Re-ran the same
`gitnexus_impact` check independently before touching anything — confirmed: risk **LOW**, 1 direct
caller, that same test.

**Fix.** Reproduced first, per TDD: added
`StudyTaskRepository_DeleteAsync_CascadesToNoteAndLinks` (seed a task with a `TaskNote` + a
`TaskReferenceLink`, call `DeleteAsync`, assert task/note/link all read back `IsDeleted == true`)
and confirmed it failed for the expected reason (`note.IsDeleted` false — the note was left live).

Extracted the cascade logic the review flagged as duplicated-in-waiting into a shared
`internal static class TaskCascadeHelper` (`Infrastructure/Persistence/SQLite/TaskCascadeHelper.cs`,
one method: `RemoveChildrenAsync(AppDbContext, Guid maTask, CancellationToken)`) and pointed both
call sites at it:
- `SqliteHocKyRepository.LuuHocKyAsync` — replaced its private `CascadeRemoveTaskChildrenAsync`
  (deleted, now dead code) with calls to the shared helper, same two call sites (MonHoc-removed
  branch, Task-removed branch).
- `SqliteStudyTaskRepository.DeleteAsync` — calls the shared helper before `db.StudyTasks.Remove`,
  in the same `SaveChanges` batch, so the seam tombstones Note/Links alongside the task.

This follows the review's stated preference (shared helper over duplicating the logic a second
time) so the two delete paths can't drift apart again.
