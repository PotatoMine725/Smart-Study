## Refine request

### M1.2-R1 — REFINE-BEFORE-ACCEPT — `DeleteAsync` breaks the G1 cascade invariant

**File:** `SmartStudyPlanner/Infrastructure/Persistence/SQLite/Repositories/SqliteStudyTaskRepository.cs` (`DeleteAsync`)

**Problem.** The method loads only the `StudyTask`, then `db.StudyTasks.Remove(existing)`:

```csharp
public async Task DeleteAsync(Guid maTask, CancellationToken ct = default) {
    using var db = _ctxFactory();
    var existing = await db.StudyTasks.FirstOrDefaultAsync(t => t.MaTask == maTask, ct);
    if (existing is null) return;
    db.StudyTasks.Remove(existing);   // no Note/Links loaded → no cascade
    await db.SaveChangesAsync(ct);
}
```

Pre-M1.2 this was a hard delete and the DB's `ON DELETE CASCADE` removed the task's `TaskNote`/`TaskReferenceLink`. Post-M1.2 the seam converts `Remove` → tombstone, so — exactly as the plan warned ("EF's `ON DELETE CASCADE` no longer fires once deletes become `UPDATE IsDeleted=1`") — the DB cascade no longer fires. The task is tombstoned but its Note/Links are left **live and orphaned**, pointing at a dead parent: the precise sync inconsistency G1 exists to prevent.

**Impact.** Latent, not active: `DeleteAsync` has **zero production callers** (I grepped — `IStudyTaskRepository` is injected only for reads in `OutcomeMaturationService`/`WeightOptimizerViewModel`; the UI deletes tasks through `LuuHocKyAsync`). Its one test (`StudyTaskRepository_AddGetUpdateDelete_RoundTrip`) uses a **childless** task, so the orphan never manifests — green but blind. The risk is a future feature wiring task deletion through this public API and silently creating orphaned live children.

**Fix.** Cascade the same way `LuuHocKyAsync` already does — remove the task's Note/Links in the same `SaveChanges` batch so the seam tombstones them too:

```csharp
var note = await db.TaskNotes.FirstOrDefaultAsync(n => n.MaTask == maTask, ct);
if (note != null) db.TaskNotes.Remove(note);
var links = await db.TaskReferenceLinks.Where(l => l.MaTask == maTask).ToListAsync(ct);
if (links.Count > 0) db.TaskReferenceLinks.RemoveRange(links);
db.StudyTasks.Remove(existing);
await db.SaveChangesAsync(ct);
```

This duplicates `SqliteHocKyRepository.CascadeRemoveTaskChildrenAsync`. Prefer **extracting a single shared helper** (e.g. a static on a Persistence helper class taking `AppDbContext`, `maTask`, `ct`) and calling it from both sites, so the two delete paths can't drift. (Alternatively, if `DeleteAsync` is genuinely unwanted, remove it from the interface + impl — but fixing is safer given it's a public API.)

**Exit check.** New test: create a `StudyTask` **with** a `TaskNote` + ≥1 `TaskReferenceLink`, call `DeleteAsync`, then assert the task **and** its note **and** its links all read back tombstoned (`IsDeleted == true` / absent via the filtered reads `GetBundleAsync`/`GetLinksAsync`). Keep the existing childless round-trip test. Full suite green; `Data` namespace stable in isolation.
